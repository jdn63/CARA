CARA - Comprehensive Automated Risk Assessment
Version: 3.0
Release date: 2026-08-01
Push: v30.0

Changelog summary:
- v30.0: NFIP retirement and observed-climate replacement. Two input
  families retired in one release because both created score
  differences no county-level measurement supported.

  NFIP flood-insurance claims removed from all scoring. Claim counts
  measure insurance participation, not flood hazard (WI Policy Forum,
  Aug 2025: Door County 60.3 policies per 10k residents, Taylor 6.5,
  Menominee zero - a county with no policies can never register a
  claim regardless of flooding). The flood score's 10 percent claims
  slice is now a NOAA storm-event flood property-damage percentile;
  the dam-failure flood proxy now counts OpenFEMA flood and
  dam/levee-break declarations (metric renamed flood_zone_overlap to
  flood_history_factor with a stored-score migration); the flood trend
  is NOAA-only; the KP HVA flood property floor triggers on 2 or more
  federal flood declarations. The NFIP fetcher, scheduler source,
  source-registry spec, and regional rollup are deleted. Flood action
  plans add the WI DHS Flood Resilience Scorecard (P-03396) and the
  DHS RAFT mapping tool, both link-verified.

  Static climate-projection multipliers retired for all five natural
  hazards. They applied one literature constant per three-county zone,
  so every county in a zone moved identically; the straight-line wind
  term added the same capped boost to all 72 counties. Replacement is
  observed NOAA nClimDiv county trends via a baked, versioned snapshot
  (recent 15-year means vs each county's own 1951-2000 baseline):
  flood gains a 5 percent observed precipitation-trend percentile, and
  the extreme-heat trend and vector-borne climate amplifier now use
  each county's measured warming. Tornado, winter storm, thunderstorm,
  and straight-line wind carry no climate term; the freed weight moved
  onto each hazard's measured NOAA event-history percentile. The
  projections JSON retains only the measured thunderstorm severity
  index. Missing-data semantics unchanged: absent inputs drop their
  term and weights renormalize, never zero-coerced.

  Also fixed in this release: the hazard trend calculator now reads
  per-category NOAA data (previously every hazard silently used the
  all-hazards event trend), and rare-for-a-county hazards go neutral
  instead of inheriting the county-wide trend. The methodology page
  documents both retirements with the participation stats. Cache keys
  bumped (dashboard_full_v19, HERC methodology version 8). Test suite:
  261 passed (35 new v30 regression tests).

- v29.0: Data honesty audit. A full pass over every displayed number and
  citation in the tool with one rule: every figure must trace to a real,
  named source or be explicitly labeled as a CARA estimate. Four
  workstreams:

  Surveillance feed cleanup. Removed the dead H5N1 and mpox surveillance
  modules (utils/h5n1_surveillance.py, utils/mpox_surveillance.py) and
  their scheduler, source-registry, and risk-weight wiring. Their
  upstream endpoints had stopped returning data, so the dashboard could
  have presented stale values as current surveillance. The biological
  panel now lists only feeds that actually refresh.

  Citation corrections. Fixed the remaining overstated source
  citations: the vector-borne deer-density provenance, the extreme-heat
  Heat Vulnerability Index attribution (now the real WI DHS HVI
  dataset), and the OpenFEMA NFIP module docstring. Deleted roughly 320
  lines of legacy synthetic-weather generation in
  utils/weather_alerts.py that could present simulated conditions as
  observations.

  Cybersecurity domain retirement. The proxy-modeled cyber score is
  retired. County baselines were hand-set constants, the tile metrics
  were derived arithmetically from the score itself rather than from
  any feed, and the citation list could not be verified. The Cyber
  Preparedness panel remains as an unscored checklist with
  authoritative links; the score is excluded from composites, regional
  aggregators, exports, and provenance. Export residual-risk resilience
  now uses FEMA NRI Community Resilience instead of the retired score.
  The action-plan cyber guidance is intentionally kept (preparedness
  advice, not a score).

  Active Shooter domain overhaul. (1) Incident history: replaced the
  truncated Gun Violence Archive file (a national reports-page export
  covering only Sep-Dec 2023, containing one Wisconsin incident) with a
  complete Wisconsin query-tool export covering 2016-2026: 71 unique
  incidents (mass shootings plus mass murders), deduplicated by GVA
  incident ID, with county attribution fixes (Hartland, Rothschild,
  Clinton) and coverage plus provenance metadata baked into
  data/gva_reports/gva_data_wisconsin.json. The manual refresh
  procedure is documented in utils/gva_data_processor.py. GVA records
  firearm incidents only; the 2021 Waukesha parade attack is therefore
  absent, and this scope limit is disclosed on the tile and methodology
  page. Data staleness is now measured from the newest incident date.
  (2) Real populations: per-capita incident rates now use Census 2020
  county populations; previously 68 of 72 counties defaulted to an
  assumed 80,000 residents. (3) Zero-incident counties now score 0 on
  the incident-history component, disclosed on the dashboard tile,
  replacing a 0.25 statewide-average placeholder that outranked nearly
  every county with actual recorded history. (4) The show-my-work panel
  now describes the real calculation, tanh(cumulative incidents per
  100k / 20); it previously described a weighted blend the code never
  computed and rendered zeros from nonexistent metric keys. (5) Lethal
  means access: removed invented firearm ownership and storage metrics;
  the component now uses a disclosed rurality adjustment from a bundled
  USDA Rural-Urban Continuum Codes 2023 snapshot
  (data/usda_rucc/wi_rucc_2023.json). (6) School vulnerability: the
  NCES SSOCS public-use ceiling (national urbanicity-class averages
  only; no state or county identifiers exist in the public file) is
  documented as a permanent limit. Citations updated across dashboard
  tiles, both methodology pages, and the HERC dashboard. Full-dashboard
  cache key advanced v15 to v18 and HERC methodology version 5 to 7
  across the pass; regression coverage added in
  tests/test_gva_wisconsin_data.py and tests/test_lethal_means_rucc.py
  (226 tests passing).

  `utils/data_processor.py` that re-mixed `socioeconomic_svi_factor`
  into the extreme-heat domain after EVR already integrated it inside
  `_calculate_enhanced_vulnerability`. Heat risk is now single-pass

  `ARCHITECTURE.md` documents the rule. (M3) `templates/methodology.html`
  updated to describe the new EPHT-canonical source hierarchy and the

  `tests/test_cache_only_invariant.py` now exercises a real integer

  Accessibility (WCAG 2.1 AA): Fixed the user-reported dark-on-dark

  Raised `.alert-warning` text to #664d03 (7.5:1 AAA), switched

- v28.8: NIHHIS Phase A. CDC Environmental Public Health Tracking (EPHT)
  introduced as the canonical observed source for the Extreme Heat
  domain's annual heat-day exposure input, replacing the prior
  synthetic statewide constant and the NCEI Climate-at-a-Glance
  monthly-max heuristic. New module `utils/cdc_epht_heat.py` fetches
  measure 421 (days >=90F per county per year) and measure 1064
  (heat-related ED visit rate) via the shared http_client circuit
  breaker, parses the per-county series, retains the latest non-null
  year per county, and persists per-county payloads to the file cache.
  A single statewide DB cache row is written so the dashboard
  freshness panel surfaces a `cdc_epht_heat` badge. Scheduler entry
  `refresh_all_cdc_epht_heat` registered in `utils/data_source_
  refresher.py`, `utils/source_registry.py` (annual cadence, 500-day
  freshness window to absorb the 12-24 month EPHT publication lag),
  and `data/config/scheduler_config.json`. `utils/extreme_heat_
  metrics.ExtremeHeatMetrics` now resolves the heat-day input via a
  provenance-aware helper that consults EPHT first, falls back to the
  NCEI heuristic (cache-only per the v28.7 explicit-failure contract),
  and finally returns None so the freshness pipeline can render an
  honest "Data unavailable" rather than a synthetic value. The
  `get_wisconsin_heat_days()` constant 12 is intentionally retained,
  untouched, only as a deeply-buried last-resort fallback in the
  elderly-population and ED-visit estimator paths where no real
  per-county replacement is yet wired. Provenance fields
  `heat_days_source` and `heat_days_year` are threaded through
  `climate_adjusted_risk.py` and `data_processor.py` into the
  extreme-heat metrics dict, and the dashboard heat tile in
  `templates/dashboard/_category_environmental.html` renders a small
  "Source: ..." caption directly under the heat-days row so the user
  can see whether the count comes from EPHT, the NCEI heuristic, or is
  unavailable. ARCHITECTURE.md updated with a CDC EPHT section
  documenting the source order, registry settings, known limitations
  (publication lag, 90F vs 100F threshold note, small-cell
  suppression, Phase B follow-ups for measure 1064 wiring), and the
  cache-only request-path invariant compliance. Mandatory triggers
  in replit.md extended with EPHT-related keywords.
